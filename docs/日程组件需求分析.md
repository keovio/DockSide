## 1. 用户场景：什么时候会瞄 DockSide 日程胶囊？

基于用户当前作息，推演真实使用时刻（按发生频率排序）：

| 场景 | 时间 | 用户状态 | 胶囊需要给什么 |
|---|---|---|---|
| **A. 起床后确认今天** | 07:30–07:45 | 刚关闹钟、喝温水、拉开窗帘，脑子还没清醒 | 一眼看到「今天 5 件事」「09:30 投递还剩 X 小时」「有没有面试」 |
| **B. 投递前 5 分钟提醒** | 09:25 左右 | 可能还在刷 BOSS 直聘、可能走神了 | 胶囊尾标「5m」+ 状态点变绿 → 立刻切到招聘 App |
| **C. 面试当天** | 不定（投递后才有面试） | 社恐焦虑，怕迟到、怕走错 | 倒计时 Xm + 进行中绿色，**不需要他主动想「我是不是该出门了」** |
| **D. 下午跟进时段** | 16:00 | 可能忘了有这个时段 | 胶囊显示「16:00 跟进回复」，提醒他坐回电脑前 |
| **E. 睡前检查** | 23:00–23:30 | 准备关手机、开勿扰 | 一眼看到「明天 09:30 投递」「明天有 X 件事」，安心放下手机 |
| **F. 跨天事件** | 23:30 后（极少） | 熬夜刷手机时 | 显示「明天 09:00 面试」——让他意识到该睡了 |

**核心洞察：用户不是「日程管理爱好者」，他是「怕忘事的焦虑型」。** 胶囊的价值不是管理日程，是**替他记住、替他倒计时、让他少焦虑一点**。

## 2. 信息优先级：胶囊里最该显示什么

按用户当前真实需求排序（不是按功能复杂度）：

| 优先级 | 信息 | 理由 | 对应规格 §2.3 状态 |
|---|---|---|---|
| **P0** | **下一条事件 + 剩余时间** | 他最怕「我是不是快迟到了」，倒计时是焦虑解药 | 进行中 / 即将开始 |
| **P1** | **今日剩余事件数（竖排环心）** | 一眼知道「今天还有多少事」，不用数 | 全部状态 |
| **P2** | **进行中状态（绿点 + 「进行中」）** | 正在做的事最容易忘（沉浸时） | 进行中 |
| **P3** | **跨天预告（明天/周X）** | 今晚睡前看到明天安排，减少「明天有什么来着」的焦虑 | 跨天即将开始 |
| **P4** | 日历色块（区分工作/个人） | 当前只有「投递」一件事，色块暂时不关键；面试多了才有用 | 可选 |
| **P5** | 全天事件 | 当前无全天事件需求（没休假、没生日） | 低优先级 |

**不要做的：**
- 不要在胶囊里显示「今天第几周 / 本周进度」——他没有周计划习惯，只会增加噪音
- 不要在胶囊里显示「日历名」——横排放不下、竖排不需要，popover 里再看

## 3. 交互需求

### 3.1 胶囊层

| 交互 | 行为 | 理由 |
|---|---|---|
| **单击胶囊** | toggle popover（今日时间轴） | 唯一主要交互，不需要多余手势 |
| **悬停胶囊** | 0.15s 展开 popover（默认开） | 鼠标一放就看，不需要点；社恐用户不想多操作 |
| **首次未授权** | 胶囊显示「授权日历」+ 单击弹系统授权框 | 一步到位，不要让他找设置 |

### 3.2 Popover 层

| 交互 | 行为 | 理由 |
|---|---|---|
| **悬停事件行** | hover 高亮 + 显示删除 x 标记 | 临时删一条错加的事件，不需要进完整窗口 |
| **单击事件行** | 本地→NSAlert 编辑 / EventKit→系统编辑器 | 复用他已有的日历习惯，不自制表单 |
| **日历筛选 chips** | 全部/工作/家庭/个人 切换 | 当前只有「工作」和「本地」两个日历，chips 够用 |
| **底部「+ 添加日程」** | 默认下一整点、1 小时 | 快速加面试/跟进，不需要精确到分钟 |
| **头部「展开完整日历」按钮** | 打开完整窗口 | 周视图是低频需求，给个入口就行 |

### 3.3 完整窗口层

| 交互 | 行为 | 理由 |
|---|---|---|
| **周/日切换** | 默认周视图 | 他一周只有 5×5=25 件投递 + 可能 0–2 场面试，周视图够用 |
| **双击空白处** | 新建事件（点击位置对应整点） | 快速加面试，比点 + 更直觉 |
| **右键事件** | 编辑/删除 | 备用入口，不常用 |

### 3.4 不需要的交互（减法）

- **拖拽调整事件**：一期不做，他没有密集日程，拖拽是伪需求
- **拖拽调整胶囊顺序**：DockSide 已有全局排序，日程组件不需要独立排序
- **右键菜单 on 胶囊**：单击已够，不要增加复杂度
- **快捷键**：macOS 组件没有快捷键入口，不做

## 4. 与现有待办 / 番茄钟的联动

DockSide 已有待办（Todo）和番茄钟（Pomodoro），日程是第三个时间类组件。联动建议：

| 联动场景 | 行为 | 理由 |
|---|---|---|
| **番茄钟进行中 + 日程即将开始** | 胶囊不额外弹 popover（番茄钟 popover 已占位），仅胶囊状态点变绿 + 尾标 Xm | 避免 popover 打架；番茄钟专注时不要打断 |
| **番茄钟进行中 + 日程已开始** | 胶囊显示「进行中」+ 剩余 Xm，不响提示音 | 他在专注，不要出声 |
| **待办到期 + 日程冲突** | 两者独立显示，不合并 | 待办是「必须做的事」，日程是「时间点」，合并反而混淆 |
| **待办「今天内」与日程同屏** | popover 里不显示待办（待办有自己的组件） | 职责分离，待办看 Todo 组件，日程看 Schedule 组件 |
| **投递 5 家（待办）vs 09:30 投递时段（日程）** | 建议：投递 5 家放 Todo（打勾用），09:30 投递时段放日程（提醒用） | 一个管「做了没」，一个管「几点做」——这是用户当前最需要区分的 |

**关键建议：** 用户当前只有「投递 5 家」这一件重复任务。**建议他把「投递 5 家」做成 Todo 待办（每天打勾），把「09:30 开始投递」做成日程事件（提醒开始）。** 两个组件各司其职，不要混在一起。

## 5. 提醒策略（产品已拍板：提示音默认关）

### 5.1 默认策略

| 提醒类型 | 默认 | 触发条件 | 可设置项 |
|---|---|---|---|
| **胶囊状态变化** | 开（静默） | 60s 刷新自动更新，无声音 | 无 |
| **提示音** | **关** | 事件开始 5 分钟前，Tink 一声 | 设置页 Toggle 打开 |
| **Popover 自动展开** | 开（悬停时） | 鼠标悬停胶囊 0.15s | 设置页 Toggle 关闭 |

### 5.2 场景化建议（供产品参考）

| 场景 | 建议行为 | 理由 |
|---|---|---|
| **面试前 5 分钟** | 如果开了提示音 → Tink 一声；胶囊尾标「5m」逼近 | 面试是关键时刻，5 分钟提醒够他准备出门 |
| **投递时段 09:30** | 不响提示音（默认关），仅胶囊状态变化 | 他已有 09:30 手机闹钟，不需要双重提醒 |
| **深夜（23:30 后）** | 即使开了提示音也静音 | 勿扰时段，不要出声 |
| **跨天事件（明天 09:00）** | 今晚 23:30 前不提醒，明天 09:25 再提醒 | 不要提前一晚上吵他 |
| **进行中事件剩余 < 5 分钟** | 胶囊尾标从 Xh 切换为 Xm，每 60s 刷新逼近 | 视觉逼近比声音更友好（社恐环境） |

### 5.3 与手机闹钟的关系

用户已在手机设了 4 个闹钟（07:30 起床 / 09:30 投递 / 11:30 收工 / 23:30 睡前）。**DockSide 日程组件的提醒是「补充」，不是「替代」：**

- 09:30 投递闹钟 → 手机闹钟响 → 他坐到电脑前 → 看到 DockSide 胶囊「09:30 投递还剩 Xm」→ 开始
- 面试提醒 → 手机闹钟可能没设（他不知道面试时间）→ DockSide 胶囊倒计时 → 他瞄一眼就知道

**结论：DockSide 的提醒策略是「静默为主、视觉优先、可选声音」，不要抢手机闹钟的活。**

## 6. 数据范围：用户关心哪些日历

基于用户当前状态，日历优先级：

| 优先级 | 日历类型 | 来源 | 在 DockSide 里的表现 |
|---|---|---|---|
| **P0** | **工作 / 求职** | EventKit（系统日历）+ 本地 JSON | 默认显示，chips 里「工作」默认选中 |
| **P1** | **本地 JSON（降级）** | `~/Library/Application Support/DockSide/schedule.json` | 授权被拒时无缝切换，不降体验 |
| **P2** | **生日 / 纪念日** | 系统日历（如有） | 当前无需求，chips 里可选；未来相亲/社交启动后可能有用 |
| **P3** | **节假日 / 全天** | 系统日历 | 全天事件区显示，不影响胶囊主信息 |

### 当前用户的日历构成（推测）

- **工作日历**：可能没有（离职后原公司日历已退出）
- **求职日程**：面试、跟进回复、投递时段——**这是当前唯一需要管理的日历**
- **个人日历**：生日、节假日——当前没有记录，未来可能有

**建议默认 chips 配置：**
- 首次授权后：chips 显示「全部」「工作」「本地」
- 默认「工作」选中（EventKit 有数据时）或「本地」选中（EventKit 无数据时）
- 「生日」chips 隐藏（没有数据时不显示空 chips）

### 数据导入导出（规格 v1.2 §5.4 已覆盖）

| 场景 | 行为 | 规格位置 |
|---|---|---|
| **换电脑 / 重装系统** | 导出 JSON → 拷到新机器 → 导入，数据迁移 30 秒 | §5.4 导出入口 |
| **面试前临时加日程** | 不需要导出，直接在 popover 里 + 添加，写入本地 JSON | §3.4 底部添加栏 |
| **误删事件** | 本地事件 x 删除（无确认）；EventKit 弹确认（不可恢复） | §3.3 事件行 |
| **备份** | 不需要手动导出——`schedule.json` 在 `~/Library/Application Support/DockSide/`，Time Machine 自动备份 | §5.4 数据文件路径 |
| **从其他日历导入** | 导入 `.ics`（主格式）→ 自动识别、按 UID 去重、弹窗反馈「已导入 N 条」 | §5.4 导入解析 |
| **导出到系统日历** | 导出 `.ics` → 拖进 macOS「日历」app → 跨设备同步 | §5.4 导出内容 |
| **批量清空** | 完整窗口底部「清空本地数据」→ 弹窗确认 → 无缝降级本地空数据 | §5.4 批量操作 |

**三处入口（规格 §5.4 已定义）：**
- 设置页 → 组件 → 日程：从文件导入 / 从剪贴板导入 / 导出 JSON / ICS / Markdown
- 完整窗口底部：导入 / 导出（下拉三选）/ 在访达显示 / 清空本地数据
- 菜单栏：导入日程… / 导出日程…（随时可用，不用先启用组件）

**支持格式：**
- 导入：`.ics`（主）、`.json`（备份恢复）、`.txt`/`.md`（简易行，如 `09:00-10:00 晨会`）
- 导出：`.json`（完整备份）、`.ics`（日历交换）、`.md`（人类可读）

**结论：导入导出功能规格 v1.2 已完整覆盖（17 条验收），客户端按 §5.4 实现即可，不需要额外加需求。**

## 7. 总结：给客户端实现的 3 条建议

| # | 建议 | 理由 |
|---|---|---|
| 1 | **胶囊默认显示「下一条 + 倒计时」**，不要显示「今天第几周」 | 他是焦虑型，倒计时是解药；周进度是噪音 |
| 2 | **提示音默认关，5 分钟前提醒面试** | 产品已拍板；面试是唯一值得声音提醒的场景 |
| 3 | **popover 里 chips 默认「工作」+「本地」**，隐藏空日历 | 当前只有求职一件事，不要让他在 chips 里找 |
