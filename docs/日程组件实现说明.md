## 2. 跟规格不一致的地方（需要设计和产品确认）

### 2.1 EventKit 事件是「读 + 写」，不是只读

规格 §5.4 写「EventKit 事件只读（不写回系统日历）」，但 §3.3 和 §4.2 又要求「EventKit 事件单击 → 编辑」「删除后弹确认，因为会写回系统日历」。两者矛盾。

**实现取的是写回**（与 §3.3 / §4.2 一致）：编辑和删除都通过 `EKEventStore.save/remove` 写回系统「日历」。删除前弹 NSAlert 确认。如果产品要的是真只读，需要改 `ScheduleIO.askEdit` 和 `askDelete` 两处，请告知。

### 2.2 新建/编辑用自制表单，不是系统编辑器

规格 §3.3 / §4.2 要求用 `EKEventEditViewController`。**这个类是 iOS 的 EventKitUI，macOS 上没有**。macOS 的自制窗口要自己搭 `EKEventEditViewController` 的等价物，工作量远大于本期。

实现用的是 NSAlert + accessoryView（标题 + 两个 NSDatePicker），与 `TodoIO.askNew` 同一套路，见 §2.3 的表单说明。如需系统编辑器体验，建议单开需求。

### 2.3 规格里几处「看着明确、实际要定」的地方

| 规格原文 | 实现做法 |
|---|---|
| chips 行「横排可换行（`FlowLayout` 简易实现）」 | 复用项目里已有的 `FlowLayout`（`LayoutEditor.swift`），没另造 |
| 「日历列表存排除集（空 = 全选）」 | 改用「已选集」：空 = 全部显示，非空 = 只显示这些。设置页的 Toggle 勾选状态才能和 chips 一致，避免两处语义打架 |
| 跨午夜事件 `≫` 角标 | 已实现：事件画到当天底部，块内显示 `≫` |
| 状态 3「损坏时忽略并重建空文件」 | 已实现：解码失败后写回一个空数组文件 |
| 状态 10「跨午夜进度环清零」 | 依赖 `TimelineView(.periodic(60))` 自然刷新，无额外定时器 |

## 3. 已实现的功能对照（规格 §7 状态表）

| # | 场景 | 实现方式 |
|---|---|---|
| 1 | EventKit 未授权 | 胶囊显示「授权日历」，点击弹系统授权框；popover 内居中「点击授权日历」按钮；竖排环心显示 `?` |
| 2 | EventKit 被拒 | 自动降级本地 JSON；popover 顶部一次性提示条 + 「查看本地数据」；可关闭且记住（`scheduleDismissDeniedTip`） |
| 3 | schedule.json 缺失/损坏 | 缺失当空处理；损坏时重建成空文件；不崩 |
| 4 | 无日程 | 胶囊「暂无日程」opacity 0.7；popover 居中「今天没有日程，享受空白吧」 |
| 5 | 只有全天事件 | 胶囊时间位显示「全天」+ 标题；popover 空态改为「今天只有全天日程」 |
| 6 | 事件进行中 | 绿点 + 「进行中」+ 剩余 `Xm/Xh`；popover 整行高亮 + now 分隔线 |
| 7 | 超长标题 | 胶囊用 `Marquee` 滚动；popover `lineLimit(1)` + `.help` 全文 |
| 8 | 跨天事件 | 胶囊「明天 HH:mm」/「周X HH:mm」；popover 时间列；周视图画到结束日列 |
| 9 | 明暗模式 | 胶囊跟随 `widgetInk`；popover 固定 dark |
| 10 | 跨午夜 | 60s 刷新自然重算 |
| 11 | 同时刻多日历重叠 | 按 start 升序、同 start 按 calendarName 排序 |
| 12 | 日历被删 | EventKit 刷新后自然消失；chips 残留名无匹配即忽略 |
| 13 | 字号 0.7× | 胶囊内全部尺寸用 `size` 倍数表达 |
| 14 | 快速划过 | 0.35s 隐延迟 + `insetBy(-6,-6)` 容差，同 TodoPopover |
| 15 | 导入 ICS/JSON/TXT | 自动识别格式、按 UID/内容去重、弹窗反馈条数 |
| 16 | 导出 JSON/ICS | 本地 + EventKit 合并导出，按 start 排序，ICS 带 `CATEGORIES` |
| 17 | 清空本地数据 | 弹窗确认后清空，EventKit 不受影响 |

## 4. 怎么跑

```bash
cd App开发组/DockSide

# 1) 跑逻辑测试（不碰你的真实数据）
./tests/run.sh

# 2) 打包成 App 并安装
./build.sh --install
```

打开后在**设置 → 布局**里把「日程」加进 Dock 旁的一侧，或在菜单栏「编辑布局」。日程设置页在**设置 → 组件 → 日程**。

## 5. 踩到的坑（给测试和维护看）

1. **`EKEventEditViewController` 是 iOS 的**，macOS 没有。规格写它是笔误，实现改成了 NSAlert 表单。
2. **Info.plist 必须加日历用途声明**，否则请求权限时进程会被系统直接终止（不是弹窗失败，是闪退）。
3. **全天事件导出 ICS 不能按 UTC 格式化**。本地 11-03 00:00 用 UTC 格式化会写成 11-02，导入回来日期就前一天。已修，测试里留了回归断言。
4. **SwiftPM 在本机受限环境跑不起来**（sandbox-exec 权限被拒），编译验证统一用 `swiftc` 直接编，测试脚本也是这么做的。
5. 项目里已有 `FlowLayout`（`LayoutEditor.swift`），新写会报重复声明——chips 直接复用它。
6. 测试脚本必须排除 App 自己的 `main.swift`，否则 swiftc 报「filename main.swift used twice」。
